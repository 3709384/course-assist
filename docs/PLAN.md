# Course Assist 项目方案

## 1. 定位

面向计算机类专业学生的 Windows 桌面工具：按课程一键配置所需的软件与开发环境，
做到「选课 → 体检 → 一键安装 → 自动验证」，让初学者不再卡在开学第一周的环境配置上。

目标用户：计算机类专业本科生（尤其是大一、大二初学者）与开设相关课程的教师。

## 2. 核心设计原则

1. **课程包数据化**：一门课 = 一个 YAML 配置文件（装什么、什么版本、怎么验证）。
   新增课程不修改代码，软件启动时可从本仓库拉取最新课程目录，本地缓存兜底。
2. **只走官方源**：安装以 Windows 官方包管理器 winget 为主通道；无 winget 包的软件
   使用官方直链 + SHA256 校验；需要付费授权或老师分发的软件提供图文指引（manual 步骤），
   绝不捆绑、绝不使用来路不明的安装包。
3. **验证才算完成**：每个工具都带验证命令，装完真实执行并检查输出，
   失败时给出明确的原因定位与修复建议，而不是只报「安装失败」。
4. **可回滚、不污染**：记录本次安装做了什么（装了哪些包、改了哪些环境变量），
   卸载/还原有据可查。

## 3. 功能规划

### MVP（第一版）
- 课程目录浏览：按分类查看全部课程与每门课的环境清单
- 环境体检：检测已安装软件与版本，与课程要求逐项对照（已装 / 版本不符 / 未装）
- **版本可选**：同一工具可提供多个版本（如 JDK 8 / 17 / 21），课程包标注推荐版本，
  用户在安装前可切换；电脑上已有其他版本时，明确提示共存方式与默认版本处理
- **安装位置可选**：安装向导询问安装根目录（默认推荐空间充足的盘，如 `D:\CourseAssist`），
  各工具装到其子目录；个别安装器不支持指定位置时回退默认路径，并在报告中如实标注实际安装位置
- 一键配置：按课程包通过 winget 静默安装缺失项，并完成这门课需要的全部配置（不只是把软件装上）
- **环境变量自动配置**：课程包声明所需环境变量（如 `JAVA_HOME`）与 PATH 追加项，
  安装后由软件统一写入用户级环境变量；写入前备份原值，可一键还原；验证阶段实际检查变量是否生效
- 验证报告：逐项执行验证命令，生成红/绿清单与失败修复建议
- 首批实测课程包：Java 程序设计、Python 程序设计、数据库系统（各附完整验证）

### 后续版本
- 课程目录在线更新（从 GitHub 拉取，新增课程无需更新软件）
- 覆盖 10+ 门主干课程的实测课程包
- 多版本管理与切换（如多版本 JDK 共存与切换）
- 体检失败的智能诊断（端口占用、旧版本残留、权限问题等常见坑）
- 环境快照导出/导入（换电脑时一键复刻整套环境）

## 4. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 桌面应用 | C# / .NET 8 + WPF | Windows 原生体验；调用 winget、注册表、环境变量最顺畅；可单文件发布，免安装运行 |
| 安装引擎 | winget（主）+ 官方直链下载（备） | 官方源、可信赖；直链必须带校验和 |
| 课程包 | YAML 文件 + JSON Schema 校验 | 对贡献者友好（会写配置就能提课程包）；CI 自动校验格式 |
| 课程目录分发 | 本仓库 `bundles/catalog.yaml`（GitHub Raw）+ 本地缓存 | 加课只改仓库，软件自动获取最新目录 |
| 测试 | xUnit（解析器、体检逻辑、验证逻辑） | 核心逻辑可测，课程包用 Schema + 干跑校验 |

## 5. 系统结构

```
src/
  CourseAssist.App        WPF 界面（课程浏览、体检报告、一键配置进度）
  CourseAssist.Core       课程包解析、体检引擎、安装编排、验证引擎
  CourseAssist.Catalog    课程目录获取与缓存
bundles/
  catalog.yaml            全部课程目录（分类 + 状态）
  <course-id>.yaml        单门课程包
  schema.json             课程包格式规范（JSON Schema）
docs/
  PLAN.md                 本文件
```

核心流程：读取课程包 → 用户选择版本与安装位置 → 体检（逐项检测） → 生成安装计划
→ 执行安装（winget/直链/manual 指引） → 自动配置环境变量 → 逐项验证 → 输出报告。

## 6. 课程包规范（摘要）

完整规范见 [`bundles/README.md`](../bundles/README.md) 与 [`bundles/schema.json`](../bundles/schema.json)。
每个工具条目包含：名称、用途说明、安装方式（winget 包 ID / 直链+校验和 / manual 指引）、
版本要求、验证命令与期望输出。课程包按状态分级：

- `verified`：维护者实机完整走通（体检→安装→验证全绿）
- `community`：社区贡献、经过格式与干跑校验，未做完整实机验证
- `draft`：草稿，仅供讨论结构

## 7. 开发排期

| 阶段 | 内容 | 产出 |
| --- | --- | --- |
| Phase 0 | 仓库与规范（本阶段） | README、方案、课程包规范、目录版图、样例课程包 |
| Phase 1 | MVP 开发 | 课程浏览、体检、winget 一键安装、验证报告；3 门实测课程包 |
| Phase 2 | 覆盖与诊断 | 10+ 门课程包、目录在线更新、常见失败诊断 |
| Phase 3 | 社区共建 | 课程包 CI 校验上线、贡献模板、多版本切换 |
| Phase 4 | 进阶 | 环境快照导出/导入、卸载还原 |

## 8. 风险与边界

- 個別软件无官方静默安装方式（老旧教学软件、需授权的商业软件）：用 manual 图文步骤兜底，不硬装。
- 学校课程要求差异大（同课不同校版本不同）：课程包支持多版本条目，由用户在体检时选择；
  社区可按学校提交变体。
- 系统差异（Win10/11、家庭版限制如虚拟机）：体检阶段先行提示兼容性，不盲目安装。
